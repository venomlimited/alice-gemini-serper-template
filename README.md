# Джарвис для Яндекс Алисы — Gemini + Serper на Vercel

Навык Алисы с персоной «Джарвиса». Отвечает через Google Gemini и подтягивает свежие данные из поиска Serper.

## Что изменилось в версии 2

**Скорость и таймауты**
- Функция работает во Франкфурте (`fra1`), ближе к серверам Яндекса. Раньше был Вашингтон по умолчанию.
- Gemini отвечает стримингом. Если к дедлайну ответ не дописан, навык отдаёт готовые предложения, а не ошибку.
- Дедлайн 3,3 с вместо 4,1 с: Алиса ждёт 4,5 с с учётом сети, остаётся запас на доставку.
- «Размышления» модели отключены (`thinkingLevel: minimal`), ответ ограничен 200 токенами, история сокращена.
- На проверочный `ping` от Яндекса навык отвечает мгновенно, не обращаясь к Gemini.
- Режим «ещё думаю» (опционально, нужен Upstash Redis). Если ответ не успевает, Джарвис просит подождать и дорабатывает в фоне. На «ну что» он выдаёт готовый ответ.

**Местоположение**
- Ташкент и текущее время передаются в промпт, модель больше не считает, что вы в Москве.
- Поиск идёт с `gl=uz`. В вопросы о погоде и местах без названного города дописывается «Ташкент».
- Часовой пояс берётся из запроса Алисы, с запасным `Asia/Tashkent`.

**Надёжность и безопасность**
- Проверка `skill_id`: чужие запросы не тратят ваши квоты.
- Результаты поиска помечены в промпте как данные, а не инструкции (защита от prompt injection). Ссылки в промпт не попадают, и модель их не зачитывает.
- Добавлено поле `tts`. По «хватит», «стоп» или «выход» навык завершает сессию.
- В логах есть время поиска, первого токена и общее время ответа, без текста пользователя.

## Структура

```
api/index.js      — вебхук: маршрутизация, дедлайн, «ещё думаю»
lib/config.js     — настройки и переменные окружения
lib/context.js    — город, часовой пояс, системный промпт, поисковый запрос
lib/gemini.js     — стриминговый запрос к Gemini
lib/search.js     — поиск Serper
lib/store.js      — Upstash Redis для фонового режима
lib/text.js       — обработка текста, интенты, история
test/             — тесты (node:test, без внешних запросов)
```

## Деплой

1. Залейте репозиторий в GitHub и импортируйте его в Vercel.
2. В Vercel → Settings → Environment Variables задайте переменные (см. `.env.example`):
   - обязательно `GEMINI_API_KEY`;
   - рекомендуется `SERPER_API_KEY` и `ALICE_SKILL_ID` (ID навыка из кабинета Яндекс Диалогов);
   - город и страна уже по умолчанию «Ташкент» и «Узбекистан».
3. В Vercel → Settings → Functions убедитесь, что включён **Fluid compute**: он сильно сокращает холодные старты.
4. В Яндекс Диалогах укажите Webhook URL: `https://<ваш-проект>.vercel.app/api`.

### Режим «ещё думаю» (опционально)

1. Vercel → Storage (или Marketplace) → Upstash for Redis → подключите бесплатную базу к проекту.
2. Переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN` (или `UPSTASH_REDIS_REST_*`) подставятся автоматически.
3. Сделайте Redeploy. Режим включится сам. Отключить его можно через `ASYNC_MODE=off`.

Без Redis навык просто отдаёт частичный ответ к дедлайну.

### Чтобы функция не «засыпала»

Если ответы после паузы всё равно приходят медленно, настройте бесплатный мониторинг (UptimeRobot, cron-job.org и т. п.): GET-запрос на `https://<ваш-проект>.vercel.app/api` раз в 5 минут.

## Как понять, где теряется время

В Vercel → Logs ищите строки `alice_request`:

```json
{"event":"alice_request","outcome":"ok","model":"gemini-3.5-flash-lite","totalMs":1840,"searchMs":610,"firstTokenMs":1350}
```

Значения `outcome`:
- `ok` — успели;
- `partial` — отдали часть ответа;
- `deferred` — ушли в «ещё думаю»;
- `timeout` / `error` — проблема.

Если `firstTokenMs` большой, дело в модели. Если большой `searchMs`, дело в поиске.

Тайминги можно подстроить переменными `RESPONSE_DEADLINE_MS`, `SERPER_TIMEOUT_MS`, `GEMINI_RESERVE_MS` (см. `.env.example`).
